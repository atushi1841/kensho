# 調査レポート（2026-10-06 / X/Twitter自動化の最新トレンド）

## 発見した情報（信頼度付き）

### 1. 公式API vs セッションクッキー型自動化の二極化（信頼度: 高）
- 公式X API v2: OAuth 2.0+PKCE必須。投稿1件$0.015（URLなし）、URL付きは$0.20。月固定費は不要だが1アプリ1アカウント制限。
  - 情報源: getxapi.com, postproxy.dev / 信頼度: 高
- サードパーティ投稿API（GetXAPI/Outstand）: セッションクッキー(`auth_token`+`ct0`)で認証。投稿1件$0.002〜$0.005。開発者ポータル不要、複数アカウント可能。
  - 情報源: getxapi.com/blog, outstand.so / 信頼度: 中（商用サービス・動作保証なし）

### 2. オープンソース・フレームワーク動向（信頼度: 高）
- **x-use-mcp** (旧 twitter-automation-ai): Python+Selenium+undetected-chromedriver。MCPツール33個、draft-gated写作、per-accountプロキシプール、RBAC。cookie import対応。PyPI公開済み。多アカウント設計がKenKhoに最も近い。
  - 情報源: github.com/bozad/twitter-automation-ai / 信頼度: 高
- **elnino-hub/x-automation**: FastAPI+curl_cffiでTLSフィンガープリント偽装。GraphQL queryId自動スクレイピング。RATE_LIMIT/AUTOMATION_DETECTED等エラー分類。n8n連携対応。
  - 情報源: github.com/elnino-hub/x-automation / 信頼度: 高
- **EmCeLDZ/XBot**: Selenium+OpenAI GPT。selenium-stealth + ランダム遅延。自己学習型エージェント。
  - 情報源: github.com/EmCeLDZ/XBot / 信頼度: 中

### 3. 検知回避の最前線（信頼度: 中高）
- curl_cffiによるChrome 136+ TLSフィンガープリント偽装が2026年のデファクト。JA3/JA4チェック绕过。
- ブラウザ自動化vs公式APIのTOS境界: Xは「APIを使わない自動化（ウェブサイトスクリプト操作）」を永久凍結対象と明記（2026年4月改訂）。公式API経由は安全ゾーン。
  - 情報源: myska-note.com / 信頼度: 高
- Playwright stealth 2026ベンチ: TLS mismatch + HTTP/2 SETTINGS frameでCloudflare/Akamaiが検知。headers乱択だけでは不十分。
  - 情報源: scrapewise.ai / 信頼度: 中

### 4. セッションクッキーの現実（信頼度: 中）
- auth_token/ct0は約12ヶ月有効。expiration後は再取得必要。
- Residential proxy必須（datacenter IPはXにブロックされる傾向）。
- 同一IPでの大量アクションはrate limit + account lockリスク増大。

## Kenshoへの適用提案

### 提案A: x-use-mcp のアーキテクチャ取り込み（優先度: 高）
- **内容**: 既存Selenium実装に undetected-chromedriver + stealth + per-account proxy pool を追加
- **期待効果**: BOTシグナル低減、長期運用安定性向上
- **実装コスト**: 中（config/accounts.json 拡張 + driver切り替え）
- **リスク**: 中等（Selenium基盤は維持、stealthは追加モジュール）
- **検討事項**: MCP対応は不要（Hermes already does this）、core機能のみ抽出

### 提案B: TLSフィンガープリント偽装の検討（優先度: 中）
- **内容**: curl_cffi導入でHTTP層の検知回避強化
- **期待効果**: GraphQL/API層のAutomated detectedエラー低減
- **実装コスト**: 高（既存Selenium + Requestsハイブリッド構成が必要）
- **リスク**: 低（fallback on seleniumあり）
- **検討事項**: Kenshoは主にDOM操作主体なので優先度B

### 提案C: セッション管理の強化（優先度: 高）
- **内容**: クッキー有効期限監視 + 自動ローテーション通知
- **期待効果**: 予期せぬSession expired停止を防ぐ
- **実装コスト**: 低
- **リスク**: 無
- **検討事項**: 即実装可能
