## 1. 今ラン最大の発見: cronスクリプト配線の回帰（検出→復旧済み）

### 現象
nightly-critic / nightly-worker / nightly-qa の3ジョブが毎回 `Script: kensho-worker-safe-wrapper.sh` を実行し、
`Script exited with code 2 / stderr: ERROR: task_id required` を出していた（本ジョブの Run Context にも記録）。

### 根本原因
`~/.hermes/scripts/kensho-worker-safe-wrapper.sh` は「agent実行をラップして rc=0 silent exit を検出する」設計で、
**第1引数に task_id を要求**する（未指定なら即 exit 2）。しかし hermes cron の `script` フィールドは
「stdout をプロンプトに注入するデータ収集スクリプト」であり、引数は渡されない。
= t_151430f8 の worker はスロットの意味を取り違えて配線しており、ラッパーは**一度も本体ロジックに到達していない**（保護効果ゼロ）。

### 実害
- 3ジョブすべてで毎実行スクリプトエラー（=毎時のノイズ・失敗記録）
- 特に **critic が `kensho-revenue-report.sh`（健康度JSON＋収益実データの注入）を失っていた**。critic プロンプトは
  「script出力の `advice.critic` が行動方針を決定する」と明記しており、入力欠落＝ルーティングが盲目化
