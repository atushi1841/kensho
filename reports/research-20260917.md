### B. 新規収益化アイデア（市場調査に基づく）

#### アイデア1: n8n自動化テンプレート販売
- **概要**: Kenshoの「収集→フィルタリング→適用」パイプラインをn8nワークフローテンプレートとしてパッケージ販売。他の懸賞自動化やデータ収集プロジェクトのテンプレートとして販売。
- **市場**: n8n Marketplaceは2025-2026年急成長中。テンプレート単品$10-50が相場。n8n公式ブログでも「template business」が取り上げられている。
- **競合**: n8n Marketplaceに自動化テンプレートは数多くあるが、「日本X懸賞自動化」ニッチは未カバー。
- **実装コスト**: 低（既存パイプラインのn8n Node設定化、ドキュメント作成のみ）
- **リスク**: 低（デジタル製品、追加インフラ不要）
- **売る労力**: 中（テンプレートのドキュメントとチュートリアル作成）
- **情報源**: n8n Marketplace 検索結果 / 類似テンプレート価格帯の観察
- **信頼度: 中**（n8n Marketplaceの正確な価格帯は調査限界。類似品観察から推定）

#### アイデア2: MCP Server 課金化（API Gateway化）
- **概要**: `japan-market-mcp`を有料MCPサーバーとして公開。AIエージェント（Claude/Cursor等）から日本市場データにアクセスする際のAPIキー課金モデル。他の開発者がAIエージェントで日本市場調査をする場面を想定。
- **市場**: MCPサーバーのエコシステムは2026年急速拡大。公式ディレクトリに掲載されると自然流入がある。
- **競合**: 現時点で日本市場データのMCPサーバーは Kensho 唯一と推定（競合稀）。
- **実装コスト**: 低（MCPサーバーは既存。認証+課金レイヤー追加のみ）
- **リスク**: 中（MCP公式ディレクトリの掲載基準不明。APIキー管理のセキュリティ対策必要）
- **売る労力**: 低（MCPプロトコル経由なのでクライアント側の設定で利用開始）
- **情報源**: MCP公式ドキュメント (modelcontextprotocol.io) / Apify MCP Actor の有料モデル
- **信頼度: 中**（MCP課金の具体的な事例がWebから取得困難。ApifyのMCP Actor有料モデルは確認済み）

#### アイデア3: ホワイトラベルデータパイプライン受託
- **概要**: Kenshoのスクレイピングインフラを他企業に貸し出し/受託。日本市場データ（カメラ/楽器/時計/奢侈品/ホットペッパー等）をリアルタイムで収集するパイプラインを構築。
- **市場**: 日本のEC/リセール市場は巨大で、競合他社もデータパイプライン構築に苦労している事例が多い。Bright Data/ScrapingBee等のB2Bデータプロバイダーが存在する。
- **競合**: Bright Data, ScrapingBee, Oxylabs（大手は高額・個人には向かない）
- **実装コスト**: 中（契約/SLA/インフラ分離の追加作業）
- **リスク**: 中（クライアントの利用目的によってはTOSリスク増大）
- **売る労力**: 高（営業/契約/カスタマイズが必要）
- **情報源**: Bright Data 価格ページ観測 / ScrapingBee モデル
- **信頼度: 中**（大手プロバイダーの存在は実在確認済み。個人向けニッチの需要は推定）

#### アイデア4: 週次マーケットレポート（有料購読）
- **概要**: 収集データを加工して「今週の日本コレクibles市場動向」レポートを週次で配信。RSS/メールニュースレター形式。$5-15/月のサブスクリプション。
- **市場**: newsletterビジネスは2026年も健在。Substack/Buttondown等のプラットフォームが整備。データ分析系ニュースレターの購読者単価は$5-20/月が一般的。
- **競合**: OtakuAlpha（類似ニッチだがAIボットベース）。Kenshoは人間が検証したデータに強み。
- **実装コスト**: 低（既存データを要約整形するだけ。メール配信基盤は既存）
- **リスク**: 低（コンテンツ作りが継続課題だがデータは自動収集）
- **売る労力**: 中（週1回の記事作成。ただしデータは自動なので作業量は少ない）
- **情報源**: Substack有料モデル / OtakuAlphaの類似サービス観測
- **信頼度: 中**（OtakuAlphaの存在はresearch_20260910.mdで確認済み。購読モデルの成否は購読者獲得に依存）

#### アイデア5: API統合ゲートウェイ（Unified API）
- **概要**: 69個のApify Actorを1つの統一APIエンドポイントにラップ。`/search?category=camera&query=canon`のように検索すると関連Actorを自動呼び出し結果を返す。ApifyのPPE課金を横断的に管理。
- **市場**: Unified API市場は2026年成長中（Postman API Network, RapidAPI等）。開発者は複数APIを統合するのが苦手。
- **競合**: RapidAPI Hub（既にKenshoのAPIはそこにあるが個別）。統合ゲートウェイは差別化可能。
- **実装コスト**: 中（ゲートウェイAPIの構築+Apify APIラッパー）
- **リスク**: 低（技術的には既存資産の組み合わせ）
- **売る労力**: 低（公開後は自然流入）
- **情報源**: RapidAPI Hub / Postman API Network / Apify Store のAPI製品
- **信頼度: 中**（RapidAPI Gatewayの具体的事例は調査限界）
