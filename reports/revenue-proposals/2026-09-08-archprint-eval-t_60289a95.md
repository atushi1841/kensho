## 対象の実態
**Archprint** = TypeScript リポジトリの import graph（実測の依存グラフ）を解析し、コードベースが既に暗黙に守っているアーキテクチャ境界を**統計的（Wilson score 下限）ゲートで検出して lint 規則に変換する**開発者向け CLI ツール。npm で公開されている無料 OSS。

- 実体: npm パッケージ `archprint`（TypeScript CLI、Node>=20）。ドキュメントは GitHub Pages（https://tommkruix.github.io/archprint/）。
- ライセンス: **MIT**（free OSS）。生成物は dependency-cruiser / eslint-plugin-boundaries / ESLint core / ts-arch 等の既存ツールが読める format を書き出す。
- 収益要素: ドキュメント実測で pricing / enterprise / cloud / saas / paid / subscription / plan の記載**一切なし**。ホスト型サービス・API・有料版ゼロ。
- 定位: 作者自身が「free OSS」として公開。研究（AgentRuleBench）の副産物であり、収益化意図は表われていない。

## 検出キーワード判定
Hunter 検出「自動化キーワード含む: あり」は誤検出。言及されている「full package workflow (scan, recommend)」「auto-enforcement of the mechanical families」「CI で自動ゲート」は、この**ツール自身の機能記述**（lint 規則の自動生成・適用）であって、Kensho が自動化して収益化できる対象ではない。開発ツール内部機能の誤検出パターンに該当。

## データの出所・独占性（決定打）
- Archprint の「2万以上の公開 TypeScript リポジトリの規則遵守率鑑定（census）」は**公開 GitHub/npm ソースの集約**であり、Kensho が取得できる独占・再現困難データではない（誰でも同様に集計可能＝コモディティ）。
- 入力は**利用者のプライベートリポジトリ**（import graph）で、Kensho のスクレイピング資産では到達不能。公開して売れるデータセットが存在しない。
- Kensho の Python scraping + LLM 要約資産と重複する再利用対象ゼロ（これは TypeScript 静的解析パイプラインであり、スクレイピング/要約商品でない）。

## 3点評価（Kensho 非API収益モデル）
### 1) プロトタイプ — 不成立
スクレイピング/販売対象の独占データが無い。census データは公開ソース由来で誰でも再現可能。ホスト型「lint-as-a-service」ラッパーを作っても、無料 MIT CLI 本体 + 確立済み無料ツール（dependency-cruiser / eslint-plugin-boundaries / Nx）と差異化できず、Kensho 資産を再利用した再現物でもない。

### 2) ローンチ手順 — 不成立
Kensho の配置経路（データAPI / 自動化 / 自前 FastAPI / Apify/RapidAPI）のいずれにも載らない。売る有料層が存在せず（元ツール無料、有料 tier なし）、「ホスト型に持ち上げる」のは新規 dev-tool スタートアップであり受動収益でない。競合飽和を確認。

### 3) 集客 — 不成立
HN score **3** / コメント **2**、GitHub stars **4** / open issues 9、npm 直近月200ダウンロード — 観客規模ゼロ級。原サイト注目度は微小（skill の却下閾値 score<20 未満）。Kensho の既存観客（国内X懸賞応募/スクレイピング/Apify系）は TypeScript dev-tool ユーザー層と重ならない。

## 結論
Archprint は MIT 無料配布の TypeScript 開発者向け CLI で、①収集・販売対象の独占データが存在しない（入力は利用者の private repo、census は公開ソース由来のコモディティ） ②有料 tier・ホスト型サービス・API・pricing ゼロ ③ドキュメント実測で収益要素記載なし ④「自動化」キーワードはツール自身の lint 自動適用の誤検出 ⑤HN score 3 / stars 4 / npm 200/mo で観客ゼロ級 ⑥Kensho の Python scraping+LLM 資産とゼロ重複。Apify/RapidAPI 以外のどの手法でも Kensho の収益商品に構成できないため却下。
