# 検証記録: Pushie（Show HN: Get notified with a simple webhook）非API収益評価（t_24709c3a）

- 対象: https://pushie.net / HN: https://news.ycombinator.com/item?id=49697912（score 19 / コメント10）
- 判断: 却下（実装対象外）— Pushieは「HTTP POST 1本で自分の全デバイスにWebプッシュ通知を届ける」個人運営の無料SaaS（作者明言: 「The idea is to stay lean so that I can offer it free」）。通知インフラは ntfy.sh（OSS・無料・自前ホスト可）/ Pushover（$5買い切り）/ Telegramボット（無料）で飽和しており、HNスレッド内で既に「So like ntfy.sh?」「I don't get the advantage over ntfy?」と指摘され、作者自身が「Not much difference」と認めている。差別化ゼロ・収益フックゼロ・データ資産ゼロの三重欠格。
- 検出側の「自動化キーワード: あり」は誤検出。本文の "start pushing to every device" は通知配信機構の説明で、自動収集・データ処理の自動化サービスではない（スキル既定の「開発ツール内部機能記述=誤検出」に該当）。

## 3点評価

### 1) プロトタイプ — 不可
- 売れるデータが存在しない。プライバシーポリシー上、通知メッセージは24時間以内に全削除、ログも7日で消える（スレッド内作者回答）。送信内容はユーザーごとにプライベートで、収集・集約・商品化できる公共データレイヤーが一切無い。
- 実測で機械可読面の貧弱さが確認できた: robots.txt 404、sitemap.xml 接続失敗、/rss・/pricing・/docs すべて404。`/api/push/<user>` は403（"Page expired" の認可ウォール）で、認可なしに叩ける公開データエンドポイントは存在しない。SPA（vue.global.prod.js + axios）の手応えのみ。
- Kensho資産（Python scraping + LLM要約 + X運用）の接続点がない: スクレイピング対象データも、継続更新される情報源もない。作れるとすれば「もう一つの無料プッシュ通知サーバー」だが、それは ntfy の再実装であり商品として成立しない。

### 2) ローンチ手順 — 不可
- Kensho 配置経路（データAPI / 自動化 / 自前FastAPI / Apify / RapidAPI / ニッチSaaS）のどれにも意味のある形で乗らない。自前FastAPIで通知中継を作る技術的コストは低いが（スレッド内で実際「trivial Node http server ... 100LOC」と自作例あり）、参入障壁がゼロのコモディティで収益化余地なし。
- 収益モデルが作者から提示されていない: 価格・プレミアム・スポンサー一切無し。「stay lean so that I can offer it free」という宣言＝このカテゴリでは無料以外的生存戦略がないことの自己申告。Pushoverが唯一成立した課金モデル（$5買い切り）だが、それはブランドと10年分の信頼の集積が必要で月1-3万円の副収入スコープの事業ではない。
- 競合飽和は一次情報（スレッド本文）で実証済み: ntfy.sh（OSS最大手で無料自前ホスト）、Pushover、Telegramボット、GitHub Actions内蔵通知等。作者はコードも「近い将来OSS化する」と表明しており、独占性はさらに希薄化する方向。

### 3) 集客 — 不可
- HN score 19・コメント10と観客規模が微小。しかもコメントの大部分は「ntfyでよくない?」という存在意義への疑念であり、関心層は通知インフラの自作能力がある開発者=自社で解決する層で、課金転換余地が最小。
- 集客アセット（属性データ / CtoA / 既存トラフィック）は移管不能。Kenshoの観客（懸賞・自動化系Xフォロワ）とは無関係のインフラ話題で、ミックスしない。

## 結論
却下。worker 実装タスク（プロトタイプ/ローンチ/集客）は切り出さない。
検出側の教訓（hunterへ回付）: 「通知・Webhook中継・プッシュ配信インフラ」系（Pushie/ntfy/Pushover互換）は、(a) 無料OSS既存最強手がスレッド内で自己申告される、(b) 配信ペイロードがプライベートデータで商品化不能、(c) 収益フック不在、の三点で自動除外できる。既存除外パターン（TokenDelivery=t_833a07b6、OSS推論ホスティング=t_0bd69b5f、OSS言語処理系=t_cf4993e8）と同枠の「コモディティ無料インフラゲート」。
