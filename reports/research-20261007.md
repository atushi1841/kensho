# 調査レポート（2026-10-07 / BOT検出・回避の最新動向）

視点: リスク（6アカウント保護）
調査対象: X（Twitter）BOT検出・凍結トリガーの2025Q4〜2026年動向
情報源: socialnexis.com / unfollr.com / fireply.ai / piunikaweb.com / note.com（Youパパ）/ HN Algolia / X公式ポリシー（help.x.com 参照元）

## 背景（重要）
- XのBOT対策は2025-10から継続的なキャンペーン（10月: リプライスパム170万アカウント削除 → 2026-02: AI系BOT強化 + APIリプライ制限 → 2026-03-12: 誤判定バグ(12hで99%復旧) → 2026-04: ピーク適用（**1分208件停止**、X製品責任者Nikita Bier公言）→ 2026-06以降も継続中）
- Kenshoの2026-09-24アカウントBAN2件（chugakujuken / inobase128508）はまさにこの継続キャンペーン中の出来事と整合
- X公式は「どのシグナルで判定したか」を明かさない → 異議申立てもトリガー不明のまま論理立てにくい（複数ソース一致）

## 発見した情報（信頼度付き）

### 1. 検出は3層構造（信頼度: 高）
- **ゲートウェイ層（全リクエスト毎）**: IP評判 / デバイス指紋（ブラウザ・解像度・フォント・ハード）/ クッキーエントロピー / **人間のタッチ入力の有無**。2024年後半にクライアントJSチェックからAPIゲートウェイへ移設済み
- **スウォーム層（座標行動）**: スレ単位のアカウントクラスタリング。**リプライ間テキスト類似度** / 新規アカウントの割合 / **同一URLが複数アカウントで重複** / 協調的行動パターン。「BOTでなくても同一クラスタに属すだけで停止レビュー対象」
- **時間パターンの層**: 固定間隔（毎正時等）の行動は「人間では出せない統計的シグナル」。**頻度より規則性が重要**（1日10回ランダム > 1日5回固定）
- 情報源: socialnexis.com/guides/x-june-2026-bot-purge-anatomy, unfollr.com/blog/twitter-automation-rules, fireply.ai/blog/x-api-reply-restriction-2026（3ソース一致）

### 2. IP評判が2026-04波で最大の打撃（信頼度: 中〜高）
- **住宅（residential）IP > モバイルキャリア > データセンター/VPS/プロキシ** の順で嫌疑スコアが下がる。クラウド系ツールは「行動が丁寧でも」送信元アドレスだけで大量停止
- 住宅IPは「最も単独で凍結を回避したシグナル」と報告
- 情報源: socialnexis.com（X公式非公開のゲートウェイ挙動の第三者分析。Xの公式文書には載っていない点に注意）

### 3. Nikita Bier 2026-02-14 本人発言（信頼度: 高・一次情報）
- 「人間が画面をタップしていなければ、**そのアカウントと関連アカウントすべて**が停止される可能性が高い — 実験目的でも」
- 多垢運用にとって「関連アカウント（associated accounts）」まで巻き込むと明言 → 6垢同時運用は単体リスク×相互連座リスク
- 情報源: piunikaweb.com/2026/03/14/x-users-report-wave-of-bans-for-inauthentic-behaviors/（元: x.com/nikitabier/status/2022496540275937525）

### 4. プロファイル完全性が隠れた加重係数（信頼度: 中〜高）
- 2026-02までに**電話番号認証済み** / デフォルト非アバター / 自己紹介記入 / **アカウント90日超** → グレーゾーン行動でも停止率が有意に低い
- 新規アカウント+自動化 = 全波の中で最もリスクの高いクラスター
- 情報源: socialnexis.com

### 5. 2026-02 APIリプライ制限（信頼度: 高）
- 公式API経由のアプリが他アカウントの投稿にリプライするには、投稿者がアプリをメンション/引用済みであることが必須になった（Xスタッフ developer forum 確認済み）
- Kenshoはブラウザ自動化（非公式API）なので**直接的影響なし**。ただし「自動エンゲージメント排除」の方向性の確認資料
- 情報源: fireply.ai（自社プロモ記事を含むため割引して評価）+ piunikaweb.com/2026/02/24/x-api-blocks-automated-spam-replies/（2ソース一致）

### 6. 現場レポート（note.com Youパパ、2026-04〜）（信頼度: 中・一次観察だが単一ソース）
- **投稿内容クラスタリング+間引き仮説**: 同ジャンルのアカウントをグループ化し、グループ内で相対評価して上位だけ残すモデル。「公式APIでも手動でもブルーバッジでも凍結」を説明
- **URL付き投稿は重点監視の可能性**: 2026-04-20 API価格改定でプレーン$0.015 vs URL付き$0.2（13倍差）→ XがURL付きに厳しい判定をする合理的動機
- **複数アカウントで同一URLを個別投稿 = 「偽証（なりすまし類似）」判定リスク** → リポストするなら元アカウントの投稿をそのまま引用RT
- 凍結歴フラグは残存 → 2回目以降の異議申立ては機械的に即却下されやすい（ただし粘れば通る事例も）
- 異議申立てベストプラクティス: AIで英語文を作成、**却下メールに最大3回返信し続ける**（「永久凍結」表記でも復活事例あり、2026-04-19頃から解除フェーズとの報告）
- 新型シャドウバン（自分から自分の投稿が見えない型）: 新内容・URL無・1時間に1投稿×3日継続で自然解除の事例
- 情報源: note.com/youpapalife/n/ncb1aac49ea7e

### 7. プライバシー系ブラウザの誤判定（2026-06）（信頼度: 中）
- Brave Browserユーザーの「inauthentic behavior」フラグ集中報告。X側はブラウザ指紋/ネットワーク挙動に依存するanti-botが誤判定を生む可能性を認める形（Elon Musk "Looking into it"）
- Firefox報告も1件 → ブラウザ指紋チェックの実運用が確認された事例
- 情報源: piunikaweb.com/2026/06/04/x-inauthentic-behavior-brave-browser-issues/

### 8. 段階的エスカレーションと異議申立て（信頼度: 中）
- 警告（イエローバナー）→ 一時ロック → 一時停止 → 永久停止 の段階。凍結は自動解除されず手動異議申立てのみ
- 応答: Premium+ 24-48h / Premium 3-7日 / Free 1-4週間。電話番号未紐付けアカウントは回復成功率が低い
- 情報源: unfollr.com（自社ツール紹介記事を含むため数値は概算として扱う）

  2. バッチ時刻が垢間で似た時間帯になり得る（時間パターンの層）
  3. 完全な人間セッション（スクロール・ dwell ・タップ）がゼロに近いアカウントがある場合のリスク（タッチ入力シグナル欠如）

## Kenshoへの適用提案

### P1: 懸賞URLのアカウント単一割当（優先度: 高）
- 提案: 各懸賞（URL単位）は**1アカウントが専属で処理**（cross_account_proximityの時間窓延期を、開始時割当の排他所有に変更）。RTは元投稿の引用RTで統一（別文での個別投稿禁止）
- 期待効果: スウォーム層の「同一URL複数アカウント」「協調行動」シグナルを構造的に排除。今回の2垢BANの最大疑因
- 実装コスト: 低（applierの割当ロジック変更。テスト既存）
- リスク: 応募総量減少（1懸賞1アカウント化）。ただし1h20アクション上限内に収まる設計で吸収可
- 優先度: **高**（2垢喪失の実害と直結）

### P2: プロファイル完全性チェック（優先度: 高）
- 提案: 各垢の電話認証・アバター・自己紹介・アカウント日数の棚卸。未達垢はユーザー操作で補完（**垢情報変更=毎回確認必須なのでユーザー要確認**）
- 期待効果: クラシファの事前確率改善（グレーゾーンでも停止率低下）
- 実装コスト: 低（確認作業のみ）
- リスク: なし
- 優先度: **高**

### P3: 時間パターンのランダム化強化（優先度: 中）
- 提案: バッチ時刻に垢別±15〜30分のジッター、日別バッチ件数±1変動、同一時刻に複数垢が起動しない排他スケジューリング
- 期待効果: 時間パターンの層（メトロノーム検出）の回避
- 実装コスト: 低（cron_worker/schedulerのパラメータ変更）
- リスク: なし
- 優先度: **中**

### P4: 週次「人間セッション」の混入（優先度: 中）
- 提案: 各垢週1回・10〜15分の実ブラウザ閲覧（スクロール・滞在・自然な2-3いいね）。タッチ入力とdwellシグナルを生成
- 期待効果: 「human is not tapping」への対抗シグナル。Bier発言で明示された最重要シグナル
- 実装コスト: 中（ユーザーの物理的介入が必要=要確認）
- リスク: 低（手動なのでBOT化しない）
- 優先度: **中**（物理操作のため毎回確認）

### P5: 凍結時プレイブック整備（優先度: 中）
- 提案: 異議申立てテンプレート（英語・人間操作の主張・ツール明示・元投稿証拠）+ 却下メールに最大3回返信継続のSOP化。凍結歴フラグ残存を前提に「1犯目は全力・2犯目は回避」
- 期待効果: 復旧率向上（現場報告: 継続返信で復活事例）
- 実装コスト: 低（ドキュメント1つ）
- リスク: なし
- 優先度: **中**

### P6: ブラウザ指紋監査（優先度: 低）
- 提案: Kensho利用ブラウザの指紋（Brave/プライバシー系設定・headless痕跡）を監査。標準的なChromeプロファイル相当か確認
- 期待効果: 指紋層の誤判定リスク低減（2026-06 Brave波の教訓）
- 実装コスト: 低〜中
- リスク: なし
- 優先度: **低**（現行で停止事例が指紋起因か未証明）

# 収益化アイデア調査（2026-10-07 別run）

## 発見した情報（信頼度付き）

### 1. Data-as-a-Service (DaaS) モデル（信頼度: 高）
- **情報源**: https://bitsfolio.com/web-scraper-paid-data-as-a-service/
- **概要**: スクレイピング結果をサブスクリプション型API/Csvで提供。月間$297〜$997、API利用課金$0.05/リクエスト。
- **成功例**: 賃貸物件データ、EC価格監視、求人情報。実績: $5,000〜$50,000/mo。
- **必須条件**: 物理的検証可能性 / 高取引速度（データ陳腐化）/ 直接商業的帰属

### 2. Productized Data Asset モデル（信頼度: 高）
- **情報源**: https://startuptrio.com/articles/productized-data-assets-profitable-b2b-digital-business/
- **具体例**:
  - 商業HVAC許可データ（$249/月、週次CSV）
  - 医療機器臨床試験コーディネーター連絡先（$499/月、35契約で$17,465 MRR）
  - 商業不動産リース満了日（$180/月/MSA）
- **収益例**: 粗利益率90%超、月間$5,000〜$15,000 MRR（ソロ運営）

### 3. AI Agent Monetization モデル（信頼度: 中）
- **情報源**: https://monday.com/blog/crm-and-sales/best-ai-agent-business-models-for-revenue/
- **価格例**: $15〜$75/候補者面談、$200/SQL、総売買収の5%
- **モデル**: サブスクリプション / 従量課金 / 成果報酬 / Agent-as-a-Service / 埋め込みエージェント / マーケットプレイス / 管理AgentOps

### 4. J-Quants API / 日本市場データ（信頼度: 高）
- **情報源**: https://www.jpx.co.jp/english/markets/other-data-services/j-quants-api/
- **概要**: 上場企業株価・財務情報・配当をAPIで提供。J-Quants Proは法人向けに追加データを提供。
