# Kensho アカウント安全性ルール

> 2026-08-12 制定。@atushi1840 / @inobase141139 の凍結（読み取り専用）を受けて作成。
> 凍結原因: フォロー→RT 5秒以内の機械的ペアパターンをXの自動検出MLに判定された。

## 1. 絶対ルール（何があっても変更禁止）

| # | ルール | 理由 |
|---|--------|------|
| A1 | アカウント別IP分離は絶対条件。`USE_PROXY=False`（全垢同一IP）禁止 | IP重複=確実にクラスターリンク |
| A2 | プロキシ死垢は自宅IPフォールバック禁止 → configコメントアウトで応募停止 | フォールバック=IP分離破綻 |
| A3 | **フォロー→RT間隔を5秒未満にしない**（アクション間待機は6〜25秒+25%で30〜90秒） | 5秒以内の完璧なペア連打が凍結の直接トリガー（実証済み） |
| A4 | **凍結検出（check_x_loginのプロフィールチェック/連続403停止）を無効化しない** | 凍結後の失敗継続=他垢とのリンクリスク |
| A5 | 1ツイートでフォロー+RT+いいねの全アクションを完璧に実行しない（skip率を維持） | 完璧な実行は機械判定される |

## 2. 必須ルール（新規垢追加・コード変更時）

- 新規アカウント追加は `x-bot-detection` スキルの「アカウント追加手順」（5ファイル+1設定）を全部実施
- `check_x_login(page, log, screen_name=...)` のscreen_name引数は必ず渡す（プロフィール凍結バナー検出が有効になる）
- アクション間待機は必ず6秒以上（5秒未満のペア禁止）
- いいねは要件なしでも10%の確率で実行（スパムプロファイル回避）
- 連続3回アクション失敗（403含む）でバッチ即中断（`[FROZEN]`ログ）
- バッチ時刻はキリ番回避・同一垢70分以上間隔・全垢ユニーク（既存ルール維持）

## 3. 凍結検出時の対応手順

1. **検出シグナル**: ログの `[NG] frozen:` / `[FROZEN]` / `[NG] suspended:` / セッションチェック異常
2. **確認**: `curl -s "https://api.fxtwitter.com/{handle}"` が `User is suspended` を返すか
3. **即時対応**:
   - config.yamlの該当アカウントブロックをコメントアウト
   - セッションファイル（data/x_session_*.json）を `data/frozen/` に退避
   - ログに `[FROZEN]` 記録日時をメモ
4. **復旧判断**: 異議申し立てはユーザーが手動で判断（自動では送信しない）
5. **再発防止**: 凍結直前7日間のaudit.jsonlを分析し、機械的パターンが無いか確認

## 4. 定期チェック

| 頻度 | 内容 | 方法 |
|------|------|------|
| 毎日 | バッチログの `[FROZEN]` / `frozen` キーワード | `grep -E "FROZEN|frozen" logs/auto_*.log` |
| 週次 | 全垢の凍結状態 | fxtwitter APIで一括確認 |
| 月次 | フォロー→RT間隔の実測 | audit.jsonlで `follow→rt 5秒以内率` を集計（60%超は要注意） |
