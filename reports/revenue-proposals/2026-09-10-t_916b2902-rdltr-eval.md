# 検証記録: Rdltr (rdltr.app) 非API収益評価（t_916b2902）

- 対象: https://rdltr.app/ / HN: https://news.ycombinator.com/item?id=49629747
- 判断: 却下（実装対象外）— 「read later」（後で読む）セーブサービス。Pocket閉鎖後に登場したInstapaper/Matter/Raindrop系の消費者向けリッスティングSaaSで、公開データはユーザー（ほぼ作者eddie自身）が保存したリンク集のみ。RSS / sitemap / topics / trends は実在するが、中身は全部 public URL の集合＝どこでも再現可能なコモディティで、Kensho資産（Python scraping + LLM要約）で収集・加工・販売できる独占的データセットが存在しない。収益モデルはPlus $30/年の消費者サブスクで、模倣はマルチテナントWebアプリ+ブラウザ拡張+iOS Shortcuts+APIの長期自社事業＝月1〜3万円の受動収益商品として不成立（ニュースアグリゲータ/キュレーション + 消費者SaaS飽和領域の却下パターン）。
- 検出は「自動化キーワード: あり」だが、これは製品内部機能（自動アーカイブ、拡張のワンクリックsave、extension/auto-save）の記述であり、自動収集・自動配信サービスではない = スキル所定の誤検出除外枠。

## 3点評価

### 1) プロトタイプ — 不可
- 公開RSS（/rss）は立つが中身が薄い: 50 item、dc:creator は eddie（作者自身）が24件、残りも twitter.com リンク20件中心等の一方的集約。先頭itemに至っては「Attention Required! | Cloudflare」（news.bakafa.com のスパム的保存）で、データ品質自体がゴミ混在。sitemap.xml は約4,900URLのうち3,924が @eddie 個人ページ（＝作者のドッグフーディング保存リスト）で、実ユーザーベースはコメント本人発言「it's mostly me for now」の通りほぼゼロ。
- データの独占性なし: 保存されているリンクは HN / Twitter / ニュース記事など全て公開ソース由来。生データは既に各元サイトに無限供給されており、「人が保存したURL」を刈っても再現困難性は無い = コモディティ。
- /api は robots.txt で Disallow かつ Bearer トークン認証の書き込み専用（curl -X POST /api/link）。読める構造化データはRSS/HTMLの個人ブックマークのみ。

### 2) ローンチ手順 — 不可
- Kenshoの配置経路（データAPI / 自動化スクリプト / 自前FastAPI / Apify/RapidAPI）に乗せられる商品性が無い。「保存トレンドデータ（topics/trends）」を販売しても、競合はPocket後継市場にひしめく Instapaper/Matter/Raindrop の公開情報そのもの。buy-inする購買者像（誰が「誰かが後で読むために保存したURLリスト」を金を出して買うのか）が構成できない。
- 本体の模倣は消費者向けSaaS事業: アカウント系、Chrome/Firefox拡張、Apple Shortcuts、bookmarklet、AI要約（外部LLM API従量課金）、Plus $30/年の決済。受動収益にするには集客・継続課金・サポートが要る長期事業。hnコメントでも「open source 0:)」への反応が「planning soon」= 非OSS。

### 3) 集客 — 不可
- HN本体は score 23 / comments 17 と観客規模が微小（スキル基準 score<20程度で却下材料の境界線上）。
- Kenshoに集客アセット（属性データ / CtoA / 既存トラフィック / 既存観客）が皆無。read-later市場はPocket閉鎖後の乗り換え需要で既に飽和（作者自身が Instapaper, Raindrop, Matter を試したと明記）、個人副収入で切り込む余地なし。

## 結論
却下。worker実装タスク（プロトタイプ/ローンチ/集客）は切り出さない。
