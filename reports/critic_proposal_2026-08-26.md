## 提案10【高・新規】RT/follow重複防止をaudit.jsonlベースに拡張（セッション跨ぎ対応）

### 状況

本日(8/26)のaudit実測で、**同一ツイートへの同一アクションが複数セッションに跨って繰り返し実行されている**ことを確認:

**全垢で合計: 同一target・同一action_typeの重複成功が数十件確認。**

### 根因分析

**applied記録の永続化が信頼できない。** 以下の証拠から、appliedは保存されるが、次回の収集マージまたは並列ワーカー保存で消失する可能性が高い:

1. 同一ツイートのappliedが一部のセッションでは保存され（13:03:43）、他のセッションでは消失する（10:08, 11:40）
2. 保存エラー・ロック失敗・マージ失敗のログは0件 → サイレント消失
3. セッション内重複防止（973efcbのrt_done_ids/followed_owners_session）は機能 → 同一セッション内の重複は防止
4. 問題は**セッション跨ぎ**: 次回セッションで _should_process_item が applied[ac]=None と判定 → 再処理

**消失の推定メカニズム（未確定）:**
- save_collected_safe のマージキーが `detail_url`（ハッシュ値）であり、収集マージが `x_url` 正規化キーであることの不整合
- 収集マージ時に `detail_url` が一致しない既存エントリが「新規追加」扱いで applied 無しで追加 → しかし x_url 重複除去で統合されるはず...

**根本原因の確定には制御実験が必要だが、appliedに依存しない防御線を別途設けることが急務。**

### 提案内容

**セッション開始時に当日のaudit.jsonlから(account, target, action_type)-successのsetを構築し、既に成功済みのtarget-actionはアクション実行をスキップする。**

```python
# セッション開始時（applier.py apply_for_account 内）
def _load_audit_done_set(account_key: str, today: str) -> tuple[set[str], set[str]]:
    """当日のaudit.jsonlから、この垢が既に成功したRTとfollowのtarget setを構築"""
    rt_done = set()
    follow_done = set()
    audit_path = ...  # data/audit.jsonl
    if not audit_path.exists():
        return rt_done, follow_done
    with open(audit_path) as f:
        for line in f:
            try: r = json.loads(line)
            except: continue
            ts = r.get("timestamp", "")
            if not ts.startswith(today): continue
            if r.get("account") != account_key: continue
            if r.get("status") != "success": continue
            tgt = r.get("target", "")
            at = r.get("action_type", "")
            if at == "rt" and tgt:
                rt_done.add(tgt)
            elif at == "follow" and tgt:
                follow_done.add(tgt)
    return rt_done, follow_done

# キュー投入時（アクション実行前）:
if target in rt_done_all:
    # 「既に当日RT成功済み → スキップ（重複アクション防止）」
    # 応募成立判定は _rt_already_done 相当で維持
    skip_rt = True
    _rt_already_done = True  # 応募成立判定に使う
```

**設計上の注意:**
- **audit.jsonlは追記専用で消えない完全履歴**（2026-07-24〜）。applied（collected.jsonの一部、収集マージで消失リスク）より信頼性が高い
- audit.jsonlの日付はUTCのため、`today` はJST変換後の日付で判定
- セッション内重複防止（rt_done_ids）は既存のまま維持（二重防御）
- **応募成立判定は `_rt_already_done` フラグで維持**（アクションはスキップしても応募成立扱い）
