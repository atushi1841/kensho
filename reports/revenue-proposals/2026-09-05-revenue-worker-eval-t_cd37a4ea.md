## 実測エビデンス

### 技術的成立性（OK、却下理由ではない）
- SUUMO robots.txt: 公開一覧ページ（/chintai/tokyo/...）は Disallow 対象外。/edit/・/mb/・/journal/・/jj/ のみ禁止 → 公開一覧の巡回はrobots上許可
- Yahoo不動産 robots.txt: /personal/favorite/・/rent/detail/*/dynamic/ 等のみ Disallow。検索/一覧ページは対象外
- 既存資産 japan-rent-market-scraper が SUUMO・at home・LIFULL の3サイト横断スクレイパーとして**実装済み・動作済み**（src/sources/{suumo,athome,lifull}.py、英/中/韓3言語 + RapidAPI rent/property OpenAPI）。スクレイピング再発明は不要

### 需要・競合（却下の核心）
1. **ポータル自社の無料新着通知が既に市場を満たしている**（niche-saas lesson #1 と完全一致）:
   - SUUMO: 無料「新着物件お知らせ」/新着メール（DDG実測で「新着物件お知らせ 無料」を確認）
   - Yahoo不動産: 無料 新着物件通知
   - LIFULL HOME'S / at home / Home's: いずれも自社ポータルで無料の新着通知を標準提供
   - 被付保の「本体価値（新規マッチ通知）」そのものが全ポータルで無料。課金SaaSとして参入余地がほぼない
2. **差別化要素（複数サイト横断 + トレンドグラフ/ヒートマップ）は差別化にならない**:
   - 複数サイト横断は既存資産（japan-rent-market）と無料アグリゲーター（住まいサーフィン等）で既に達成済み
   - 家賃トレンド/ヒートマップは公開相場データの派生物で、非対称性ゼロ（SUUMO/ホームズ/Yahoo が家賃相場を無料表示）。公開相場データは誰でも見られ、競争優位にならない
3. **同一データ資産の需要が未検証のまま30日以上経過**（Apify portfolio API 実測 2026-09-05）:
   - japan-rent-market-scraper: `isPublic=false` / runs=25(全て自己実行) / users=1 / u30d=0 / u90d=0
   - japan-property-market-scraper: `isPublic=false` / runs=25 / users=1 / u30d=0 / u90d=0
   - ポートフォリオ全体も外部run=0・収益0円9日目（QA v26実測）。同一供給側データで課金SaaSを積むのは、未検証需要に実装コストを重ねるだけ
4. **TOSリスク**（robots許可≠商用転載許可）: 賃貸一覧データを有料SaaSで再配布・通知するのは LY Corp(Yahoo) / Recruit(SUUMO) の利用規約と抵触し得る。実装コストに加え法的リスクを課すが見返りとなる検証済み需要が無い

## 結論
- 本機会は「ポータル自社が無料提供する通知/アラート機能に課金SaaSとして参入」する none = **car-price-alert と同型の却下パターン**。プロトタイプ・ローンチ手順・集客の着手は行わない。
- 同一データ資産の需要は japan-rent-market（英/中/韓）+ RapidAPI rent/property で検証済みだが30日でu30d=0 → 需要が出る前にSaaS化するのは時期尚早どころか無益。
- 見直し条件（このいずれかが明確に出た場合のみ再評価）:
  1. japan-rent-market / RapidAPI rent で**外部ユーザー有償利用が実測された**（u30d≥数件 or RapidAPI売上>0）
  2. ターゲットを**企業向け**（不動産仲介事業者の相場分析/物件監視）に限定し、個別営業型B2Bとして再設計
